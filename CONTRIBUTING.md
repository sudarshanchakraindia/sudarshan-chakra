## 🤝 Code of Conduct

Be respectful, inclusive, and constructive. This project serves diverse communities across language and religion — treat all contributors with the same values.

---

## 🚀 Getting Started

1. **Fork** the repository (for external contributors)
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/YOUR_USERNAME/sudarshan-chakra.git
   cd sudarshan-chakra
   ```
3. Open the project in your browser or a local server (e.g. VS Code Live Server)

---

## 🌿 Branching Strategy

Never commit directly to `main`. Always work on a feature branch:

```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/bug-description
```

**Branch naming conventions:**
- `feature/` — new functionality
- `fix/` — bug fixes
- `docs/` — documentation updates
- `style/` — UI/CSS changes
- `refactor/` — code restructuring

---

## ✏️ Making Changes

- Keep changes focused — one feature or fix per branch/PR
- Test your changes in a browser before submitting
- Ensure HTML is valid (use the W3C validator or the built-in CI check)
- Do not commit sensitive data (API keys, Firebase credentials, etc.)

---

## 📬 Submitting a Pull Request

1. Push your branch to GitHub:
   ```bash
   git push origin feature/your-feature-name
   ```
2. Open a Pull Request against `main`
3. Fill in the PR template completely
4. Request a review if collaborators are available
5. Wait for CI checks to pass
6. Merge only after approval

---

## 💬 Commit Message Guidelines

Use clear, descriptive commit messages:

```
type: short description (max 72 chars)

Examples:
feat: add voice command support for service search
fix: correct distance calculation on hire_checkout page
docs: update README with deployment instructions
style: improve mobile layout for gratitude page
```

Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

---

## 🐛 Reporting Bugs

Use the Bug Report issue template and include:
- Steps to reproduce
- Expected vs actual behaviour
- Browser and OS details
- Screenshots if applicable

---

## 💡 Requesting Features

Use the Feature Request issue template and describe:
- The problem you want solved
- Your proposed solution
- Why it benefits the platform's users
